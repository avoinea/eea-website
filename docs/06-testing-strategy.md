# 06 — Testing Strategy

## Overview

| Pipeline | Unit tests | Acceptance tests |
|---|---|---|
| **Volto 18** (`eeacms/frontend-builder:18`) | ✅ Vitest | ✅ Cypress |
| **Volto 19** (`eeacms/frontend-builder:19`) | ✅ Vitest | ✅ Cypress |

Both pipelines are **pnpm** and run the **same** add-on test suite. Volto 18 ships `vitest.config.mjs` (not just Jest), so the add-on's Vitest tests run on Volto 18 too — no need to maintain a separate Jest setup or skip unit tests on Volto 18.

## The add-on's `@plone/razzle` babel is V19-only — but that's fine

`babel.config.js` uses `@plone/razzle` (the Volto 19 fork), which is absent on Volto 18 (Volto 18 has `razzle`). However, the add-on's `babel.config.js` is only loaded by `make i18n` (the add-on's i18n extraction) — **not** by the CI stages (`lint`, `test-ci`, `start-ci`, `cypress-ci`). So `@plone/razzle` being missing on Volto 18 doesn't break CI.

## Vitest for both versions

Volto 19 removed Jest from core and switched to Vitest. Addons need a `vitest.config.mjs` file. Most existing test files work as-is because Vitest has a Jest-compatible API (`describe`, `it`, `expect`).

### What changes in test files

| Jest API | Vitest equivalent | Action needed |
|---|---|---|
| `describe`, `it`, `expect` | Same | None |
| `jest.fn()` | `vi.fn()` | Conditional or migrate |
| `jest.mock()` | `vi.mock()` | Conditional or migrate |
| `jest.config.js` | `vitest.config.mjs` | Replace config file |

### Vitest config for addons

Generated by the `frontend_addon` Cookieplone template:
```js
// vitest.config.mjs
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./setup-tests.js'],
  },
});
```

## Cypress for both versions

Cypress remains the cross-version acceptance testing layer. Volto 19 still uses Cypress natively — the Cookieplone templates, Docker images, and Volto core all expect it.

### The `rm -rf /app/cypress` overlay (important)

The add-on Dockerfile does `rm -rf /app/cypress` **before** copying the add-on's `cypress/` onto the base. The base image (`plone/frontend-builder`) ships an **upstream Volto** `cypress/support/e2e.js` that uses `reset-fixture` → `POST /Plone/RobotRemote`. The EEA backend doesn't expose `/Plone/RobotRemote`, so that upstream cypress 404s. `rm -rf /app/cypress` ensures the add-on's **EEA** cypress (`slateBeforeEach`, which creates content via the REST API) replaces the base's upstream one.

### `cypress.config.js` (EEA override)

The EEA `cypress.config.js` adds:
- `reporter: 'junit'` + `reporterOptions.mochaFile: 'cypress/reports/cypress-[hash].xml'` — so the EEA Jenkinsfile can publish Cypress results (`junit testResults: 'cypress-results-current/**/*.xml'`). Without the JUnit reporter, `docker cp /app/cypress/reports` fails (the dir isn't created) → CI red.
- `@cypress/code-coverage/task` in `setupNodeEvents` — registers the coverage task so `cypress/support/e2e.js`'s `@cypress/code-coverage/support` has somewhere to send coverage. (Coverage is only collected when the frontend is built/started with `babel-plugin-istanbul` instrumentation — see `make start-ci`. Without instrumentation, coverage is empty but non-fatal.)

### `check-ci` uses bash `/dev/tcp`, not `curl`

`plone/frontend-builder` (and `eeacms/frontend-builder`) does **not** install `curl` or `wget`. The EEA `make check-ci` waits for the frontend with bash's built-in `/dev/tcp`:

```makefile
check-ci:
	@timeout 600 bash -c 'until (echo > /dev/tcp/localhost/3000) 2>/dev/null; do sleep 2; done'
```

The 600s timeout covers `make start-ci`'s `pnpm build && pnpm start:prod` (the production build of Volto takes a few minutes in CI).

### What stays the same
- Cypress config (`cypress.config.js`)
- Custom Cypress commands
- Test fixtures
- `@testing-library/cypress` integration
- `cypress-axe` for accessibility testing

### What changes
- Cypress tests may need path updates (`src/addons/` → `packages/`) if they reference addon paths directly
- The CI Docker image for Volto 19 testing needs to be a pnpm-based Volto 19 project

## Playwright — deferred

Playwright was considered but deferred:
- Volto 19 still uses Cypress natively
- Migrating to Playwright is a separate project, not part of this upgrade
- All existing Cypress tests, custom commands, and EEA CI infrastructure continue to work
